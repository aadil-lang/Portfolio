## Chapter 10: VM Copy Question Generator

### Context & Period
* **Period:** October 2025 – November 2025  
* **Organization:** Wayground (Quizizz)  
* **Role:** Creator & Lead Developer  
* **Ownership:** `INDEPENDENTLY BUILT` *(Independently architected and deployed)*  

### Context & Background
Independently architected and deployed full-stack web application designed to generate isomorphic math question variants automatically while eliminating manual copy-paste friction.

### Problem & Why It Mattered
Curriculum authors needed multiple isomorphic variants of base questions. Monolithic single-prompt requests to LLMs frequently timed out or degraded in quality when processing multiple items at once.

### Use Case
Generating structured mathematical question variants from base items.

### System / Approach
```text
BASE QUESTION
  ↓
VM COPY UI (Next.js 16)
  ↓
PARALLEL MICRO-BATCH DISPATCH (`calculateBatches`)
  ↓
PORTKEY AI GATEWAY
  ↓
STRUCTURED LLM GENERATION
  ↓
DETERMINISTIC EVALUATION (`lib/eval-layer.ts`)
  ↓
VERIFIED VARIANTS DISPLAY
```

### My Role & Ownership
* **Ownership:** Independently architected and deployed.
* **Role:** Full-stack creator and sole developer.

### Architecture Rationale
1. **Why separate UI and API?** Allowed authors to input base questions easily while backend API routes managed model communication asynchronously.
2. **Why parallel micro-batches (`calculateBatches`)?** Monolithic requests timed out at 30s. Partitioning requests into small parallel micro-batches bounded latency to ~4–6s and prevented gateway timeouts.
3. **Where was AI used?** Generating stochastic text variants of math word problems.
4. **Where was deterministic logic used?** Request partitioning, gateway routing, and output evaluation.
5. **Trade-offs:** Required managing parallel Promise resolution and handling partial batch failures gracefully.

### Technical Stack Specimen
```text
INTERFACE       Next.js 16 (App Router) / React 19 / Tailwind CSS
APPLICATION     TypeScript 5 API Routes / Node.js
ORCHESTRATION   Parallel Micro-Batch Dispatch (`calculateBatches`)
MODEL           OpenAI / Portkey AI Gateway
VALIDATION      Tier-1 Deterministic Evaluator (`lib/eval-layer.ts`)
INFRASTRUCTURE  Vercel / Edge Network
```

### Validation
Tested across hundreds of math question inputs; verified batch completion latency under 6 seconds.

### What I Learned
Wrapping an LLM inside a structured application with micro-batching transforms unreliable chat interactions into a responsive production workflow.

### New Limitation / Question
> Generating structured text is solved, but how do we automatically verify that the generated question is structurally valid?

### Next System Connection
Led directly to building the Tier-1 Deterministic Evaluator (`lib/eval-layer.ts`).

## Chapter 11: Generation is Not Evaluation

### Context & Period
* **Period:** Late 2025  
* **Organization:** Wayground (Quizizz)  
* **Role:** Lead Developer  
* **Ownership:** `INDEPENDENTLY BUILT`  

### Context & Background
Built `lib/eval-layer.ts` (`evaluateDeterministic`), an in-memory, zero-cost TypeScript evaluation module running outside the model to validate generated math questions against strict structural rules.

### Problem & Why It Mattered
Model outputs frequently broke structural rules: generating 3 or 5 options instead of 4, marking zero or multiple options as correct (`logic: "CA"`), or duplicating distractor text. Calling another LLM to check these rules was slow, expensive, and unreliable.

### Use Case
Instant, 0ms, $0 server-side validation of generated multiple-choice math questions.

### System / Approach
```text
GENERATED QUESTION CANDIDATE
  ↓
lib/eval-layer.ts (evaluateDeterministic)
  ├── 1. Check Option Count === 4
  ├── 2. Check Exactly 1 Correct Answer (logic: "CA")
  ├── 3. Check Distractor Uniqueness (Set-based)
  └── 4. Check Non-Empty Explanation String
  ↓
PASS / FAIL SCORE + REASON CODES
```

### My Role & Ownership
Independently designed and implemented the evaluation algorithms in TypeScript.

### Technical Stack
* **Language:** TypeScript 5
* **Execution:** In-Memory Server-Side / Client-Side Module
* **Cost / Latency:** $0 cost, 0ms execution time

### Validation
Covered by unit tests verifying detection of option cardinality errors, duplicate distractors, and missing correct-answer flags.

### What I Learned
Generation and validation are separate engineering problems. Explicit structural rules must be enforced by deterministic code outside the model.

### New Limitation / Question
> What happens when I join the formal engineering team to build enterprise-scale AI pipelines?

### Next System Connection
Led to formal transition into the Wayground AI/ML Engineering Team in January 2026.

## Chapter 14: AI Worksheets

### Context & Period
* **Period:** February 2026 – March 2026  
* **Organization:** Wayground (Quizizz)  
* **Role:** Full-Stack Lead Engineer (Wayground Company POC)  
* **Ownership:** `INDEPENDENTLY BUILT` *(Company Proof of Concept)*  

### Context & Background
Built a full-stack company POC automating TEKS-aligned printable math worksheets pairing multi-model LLM generation with Dockerized `pdflatex` compilation pools and deterministic 2D backtracking solvers.

### Problem & Why It Mattered
Generative models cannot draw mathematically accurate vector diagrams (angle arcs, coordinate planes) or solve 2D spatial puzzle grids (crosswords, mazes) without physical compiler and graph solver integration.

### Use Case
Generating printable, TEKS-aligned math worksheets with compiled TikZ diagrams and 2D spatial puzzles.

### System / Approach
```text
TEKS TOPIC SELECTION
  ↓
FASTAPI ASYNC BACKEND
  ├── LLM MODEL ROUTING (Portkey: GPT-4o for math, Gemini 3 Flash for layout)
  ├── 2D BACKTRACKING SOLVERS (Word searches, maze grid logic)
  └── DOCKERIZED COMPILATION POOL (TeX Live pdflatex + TikZ → PNG/PDF)
  ↓
REACT 18 / VITE 6 FRONTEND PREVIEW & PDF DOWNLOAD
```

### Architecture Rationale
1. **Why FastAPI + Docker?** Asynchronous Python backend was necessary to manage heavy subprocess pools (`pdflatex`) and CPU-bound 2D backtracking solvers cleanly.
2. **Why Portkey multi-model routing?** Routed text generation to GPT-4o and spatial layout heuristics to Gemini Flash, optimizing cost and quality.
3. **Why 2D backtracking solvers?** Spatial puzzle grids require 100% mathematical solvability that LLMs cannot guarantee.
4. **Where was AI used?** Generating narrative word problems and lesson instructions.
5. **Where was deterministic logic used?** Puzzle grid backtracking, TikZ compilation, and PDF rendering.

### Technical Stack Specimen
```text
INTERFACE       React 18 / Vite 6 / Tailwind CSS
APPLICATION     FastAPI / Python 3.12 / Asyncio
ORCHESTRATION   Portkey Gateway / Multi-Model Router
MODEL           OpenAI GPT-4o / Gemini 3 Flash
COMPILERS       TeX Live (`pdflatex`) / TikZ Subprocess Pool / Poppler
SOLVERS         2D Backtracking Solvers (Python)
INFRASTRUCTURE  Docker Compose / PostgreSQL / Redis / MinIO
```

### Validation
Automated PDF compilation checks verifying zero TeX log errors and 300-DPI PNG image rendering.

### What I Learned
AI applications quickly become multi-system engineering problems. The language model generates narrative text; deterministic compilers and graph solvers generate layout logic and graphics.

### New Limitation / Question
> How do we handle large-scale curriculum document transformations across thousands of state standards?

## Chapter 17: Curriculum Transformation — Phase 2

### Context & Period
* **Period:** July 2026  
* **Organization:** Wayground (Quizizz)  
* **Role:** Backend Data Engineer  
* **Ownership:** `INDEPENDENTLY BUILT` *(Independent Production Build)*  

### Context & Background
Engineered a production asynchronous Map-Reduce ETL pipeline transforming massive, unstructured state curriculum documents into normalized tabular datasets.

### Problem & Why It Mattered
Processing 500-page curriculum standards sequentially caused timeouts and schema drift. Naive scrapers dropped standards codes or corrupted hierarchy alignments.

### Use Case
Batch transforming state curriculum standards into validated tabular databases.

### System / Approach
```text
UNSTRUCTURED PDF / DOCX DOCUMENT
  ↓
DOCUMENT CHUNKING & MAP DISPATCH
  ↓
ASYNCHRONOUS CELERY / REDIS WORKERS
  ↓
STRICT JSON TOOL CALLING (Claude 3.5 Sonnet)
  ↓
DYNAMIC PYDANTIC SCHEMA CONTRACT SYNTHESIS
  ↓
REDUCE & MERGE WORKER
  ↓
THREE-TIER INTEGRITY GATE (Reviewer → Critic → CSV Audit)
  ↓
NORMALIZED TABULAR DATASET
```

### Architecture Rationale
1. **Why Map-Reduce?** Bounded memory footprint and enabled parallel processing of document chunks across distributed Celery workers.
2. **Why Dynamic Schema Contract Synthesis?** Derived schema contracts dynamically from sample data layouts rather than maintaining fragile hardcoded scrapers.
3. **Why 3-Tier Integrity Gate?** Three sequential validation layers (Reviewer checking schema, Critic checking logic, CSV Audit verifying row counts) guaranteed zero corrupted exports.

### Technical Stack Specimen
```text
APPLICATION     Python 3.12 / Asyncio / Pandas
WORKERS         Celery / Redis Asynchronous Task Queue
MODEL           Claude 3.5 Sonnet / Strict JSON Tool Calling
VALIDATION      Dynamic Pydantic Contracts / 3-Tier Integrity Gate
EXPORT          CSV Audit Engine / PostgreSQL
```

### Validation
Processed complex state curriculum documents with 100% row alignment and zero schema drift reported in CSV audit logs.

### What I Learned
Large document transformations require decomposition, dynamic schema contracts, asynchronous worker pools, and multi-tier verification gates.
