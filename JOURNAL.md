## Chapter 12: From Generation to Evaluation
**Subtitle:** Tier-1 Deterministic Evaluator  
**Period:** Feb 2025 — Mar 2025  
**Organization:** Wayground (Quizizz)  
**Role:** Independent Developer  
**Journey Stage:** Deterministic Evaluation  
**Ownership:** Wayground · Independent Build  
**Connected System:** [`vm-copy`](file:///c:/Users/HP/Documents/Portfolio/app/systems/vm-copy)  

* **Problem:** Generated items frequently broke option cardinality (3 or 5 options), had 0 or >1 correct answers, or duplicated distractors.
* **Solution:** Engineered `lib/eval-layer.ts` (`evaluateDeterministic`): in-memory TypeScript evaluator enforcing exactly 4 options, exactly 1 CA, and Set-based duplicate distractor rejection.
* **Breakthrough:** Decoupling generation from validation: structural validation must happen deterministically without calling another model.
* **What Became Deterministic:** Option cardinality (exactly 4), answer key exclusivity (single CA), distractor uniqueness, step-by-step format compliance.
* **Accumulated Capability:** Deterministic evaluation layer, TypeScript AST/string validation, invariant scoring.
* **Technologies Used:** TypeScript, In-Memory Evaluator, Invariant Testing

## Chapter 19: The Reliability Question

**Role:** AI Systems & Reliability Engineer

* **Accumulated Capability:** Playwright headless browser diagnostics, Fisher covariance uncertainty filtering, MCP tool protocols, SHA-256 cryptographic provenance.
* **Technologies Used:** Python 3.12, FastAPI, Playwright (Chromium), Ollama (Qwen 2.5), MCP Integration, Fisher Covariance, SQLite, SHA-256 Ledger
