## 4. Central Publication Restriction & Information Boundary Enforcement

A critical security and IP governance vulnerability in legacy code was the exposure of internal employer repositories through public portfolio files. Although `canonicalRegistry.ts` recorded `repository.publicUrl: null` for proprietary systems, legacy `data/projects.ts` and `data/canonical/projectsMetadata.ts` hardcoded active GitHub links to internal repositories for `vm-copy`, `ai-worksheets`, and `curriculum-etl`.

### Central Enforcement Mechanism
In `data/adapters/projectsAdapter.ts`, all public URL derivation is routed through a single deterministic gate:

```typescript
export function getGovernedProjectPublicUrl(canonicalProj?: CanonicalProjectRecord): string | null {
  if (!canonicalProj) return null

  if (
    canonicalProj.ipOwnership === 'EMPLOYER_PROPRIETARY' ||
    canonicalProj.publicationEligibility !== 'PUBLIC_OPEN_SOURCE' ||
    canonicalProj.repository.isPrivateOrProprietary
  ) {
    return null
  }

  return canonicalProj.repository.publicUrl || null
}
```

### Code Evidence Sanitization
Furthermore, `projectsAdapter.ts` implements automated code evidence sanitization:

```typescript
function sanitizeCodeEvidence(
  evidenceList: CodeEvidence[] | undefined,
  isProprietary: boolean
): CodeEvidence[] | undefined {
  if (!evidenceList) return undefined

  return evidenceList.map((item) => {
    if (isProprietary) {
      const { sourceUrl, ...rest } = item
      return {
        ...rest,
        sourceUrl: undefined
      }
    }
    return { ...item }
  })
}
```

### Adversarial Bypass Verification
Test Suite 2 includes an adversarial regression assertion that constructs a mock `EMPLOYER_PROPRIETARY` project record injected with a spoofed `publicUrl: 'https://github.com/leaked/proprietary-repo'`. Passing this record through `getGovernedProjectPublicUrl()` returns `null`, proving that no consumer can bypass the publication boundary.
